# 3. 系统设计（超级重点）

- 狭义设计 ≈ 概要设计。软考用广义：概要设计 + 详细设计。
- 概要设计：框架、组成、关系。详细设计（模块设计）：接口、算法、内部实现。
- 结构化设计的四个活动：**数据设计、软件结构设计、人机界面设计、过程设计**。选择题爱考这四个。

七类设计里，代码设计（含 OO 与结构化）和处理流程设计是重点。界面黄金三原则：用户控制、减轻记忆、保持一致。

## 3.3 处理流程

流程（ISO 9000）：一组将输入转化为输出的相互关联的活动。

六要素：输入资源、活动、活动的相互作用、输出结果、用户、价值。

| 概念 | 区别 |
| --- | --- |
| 流程 | 输入变输出的一组活动 |
| 工作流 | 可自动执行、按规则在执行者之间传递文档和任务 |
| 活动 | 流程的基本要素；所有者有权结束活动并推到下一步 |
| 工作项 | 某个流程实例里，某个参与者要做的那一件具体事 |

流程设计工具分三类：

- 图形：程序流程图 PFD、N-S 盒图、IPO 图、PAD、判定树
- 表格：判定表
- 语言：PDL 伪代码

易错：PFD 描述程序逻辑，**不**用来描述模块的输入、输出和加工（那是 IPO）。

工作流管理系统 WFMS 三大功能：建模、执行、过程管理与分析。口诀：简直过分。

工作流参考模型六块：工作流执行服务、引擎、流程定义工具、客户端应用、调用应用、管理监控。口诀：指引丁克调管。

## 3.4 面向对象设计（重点）

OOD 是 OOA 的延续。思想：抽象、封装、可扩展（继承 + 多态）。数据与操作封装在同一对象里。

**三类设计类（案例判断）**

| | 实体类 | 控制类 | 边界类 |
| --- | --- | --- | --- |
| 是什么 | 要持久保存的业务对象 | 控制用例怎么往下走 | 系统与外界的交界 |
| 命名 | 业务名词 | 动宾转成的名词 | 窗口、协议、接口、报表 |
| 寿命 | 业务在就在 | 用例结束就消亡 | 随系统运行存在 |
| 判断顺序 | 先看是不是界面/协议/打印机/报表 → 边界类；剩下名词 → 实体类；动名词 → 控制类 | | |

**设计原则（论文和案例都可能问）**

| 原则 | 一句话 |
| --- | --- |
| 单一职责 S | 一个类只有一个设计目的 |
| 开闭 O | 对扩展开放，对修改关闭。其他原则的基础 |
| 里氏替换 L | 用父类的地方可以换成子类 |
| 接口隔离 I | 不要强迫客户依赖用不到的方法，大接口拆小 |
| 依赖倒置 D | 抽象不依赖细节，针对接口编程。实现开闭的主要手段 |
| 组合/聚合复用 | 优先用组合而不是继承 |
| 最少知识（迪米特） | 只和直接朋友通信 |

SOLID = S O L I D。另外两个是组合复用和迪米特。

## 3.5 结构化设计（重点）

面向数据流。基础是 SRS、DFD、数据字典。自顶向下、逐步求精、模块化。原则：**高内聚、低耦合**。

模块划分：大小适中（约 50～200 行）；扇出是调用的下级个数，扇入是被多少上级调用，平均扇入扇出 3～4，不超过 7；深度是层数，宽度是同一层模块数的最大值；信息隐蔽，模块做成黑盒。

**耦合从低到高**（非直接最低，内容最高）

1. 非直接：只通过主模块间接联系
2. 数据：传简单数据
3. 标记：传记录 / 数据结构
4. 控制：传的信息用来控制对方内部逻辑
5. 外部：都访问同一个全局简单变量
6. 公共：都访问同一公共数据环境（全局结构、共享区）
7. 内容：直接访问内部数据、转到内部、代码重叠、多入口

**内聚从高到低**（功能最高，偶然最低）

1. 功能：只做一件事
2. 顺序：必须按序，且前一个的输出是后一个的输入
3. 通信：都集中在同一数据结构上
4. 过程：必须按特定次序，但**不一定有数据传递**
5. 瞬时（时间）：必须在同一时间段做
6. 逻辑：逻辑上相关的一组任务
7. 偶然：毫不相干硬凑在一起

顺序 vs 过程：有没有数据依赖。

## 3.6 设计模式（次重点，多在选择）

创建 5：工厂方法、抽象工厂、生成器、原型、单例。口诀：工厂抽象建造者，单例原型巧构成。

结构 7：适配器、桥接、组合、装饰、外观、享元、代理。口诀：试桥组装外享代。

行为 11：责任链、命令、迭代器、中介者、备忘录、观察者、状态、策略、模板方法、访问者、解释器。口诀：观察命令责任链，迭代模板状态变。中介策略备忘录，解释访问都包含。
