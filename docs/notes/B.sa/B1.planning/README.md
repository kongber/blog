# 1. 系统规划与分析（次重点）

系统分析的产物是**系统需求规格说明书**。分析内容：问题分析、业务流程分析、数据与数据流程分析（用 DFD，放到第 2 章）、可行性分析、成本效益分析。

## 1.1 因果分析（重点）

先问「问题是什么」，不要把功能需求当成问题。

**问题—机会—目标—约束矩阵**（从左到右填）：

1. 问题或机会：写现象，如「订单响应时间不可接受」，不要写解决方案。
2. 原因和结果：为什么、造成什么影响。
3. 系统目标：可衡量、可验证，如「处理时间减少 30%」。
4. 约束：不能加人、必须兼容某环境、不能推翻已批系统。

**鱼骨图**（石川图 / 因果图）：鱼头是结果，大骨是原因类别，小骨是细因。

- 制造：人、机、料、法、测、环
- 信息系统可改成：人员、流程、数据、系统、接口、设备、管理、外部环境
- 鱼骨图横向展开原因；**5Why 纵向追根因**。二者一起用。
- 5Why 的「5」不是死次数。局限：复杂问题往往多因，不能只追一条线。

## 1.2～1.4 业务流程（次重点，会辨析）

| 方法 | 要点 |
| --- | --- |
| 价值链 | 找竞争优势，含基本活动和辅助活动 |
| 客户关系 | 以客户为导向 |
| 供应链 | 从内外部供应链看核心环节 |
| 基于 ERP | 把流程看成供应链来优化资源 |
| 业务流程重组 | 以顾客满意为出发点重审价值链 |

工具：业务流程图 TFD（事务处理、部门分工、物流信息流、系统边界）；业务活动图 BAM（识别、描述、优化流程）。

BPM 建模（只考概念，不考画图）：

| 方法 | 一句话 |
| --- | --- |
| 标杆瞄准 | 对标领先企业的最佳实践 |
| DEMO | 基于对话行为，业务事务分要求、执行、结果 |
| Petri 网 | 形式化、图形直观、基于状态，可仿真 |
| 建模语言 | 文本类 BPEL、BPML；图元类 BPMN、UML；XPDL 两者都有 |

## 1.5 可行性（重点，选择 / 案例 / 论文都考过）

| 类型 | 看什么 |
| --- | --- |
| 经济 | 成本与收益，早期只能粗估 |
| 技术 | 现有技术与资源能否支撑，要和功能、性能、约束同步看 |
| 法律 | 不抵触法律政策，不违规用构件 |
| 用户使用 | **管理者视角**：领导是否支持（管理可行性）+ 是否好用、对组织的影响（运行可行性）。领导不支持容易失败 |
| 进度 | 资源约束下能否按时，区分强制期限和期望期限 |
