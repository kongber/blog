# 5. 系统架构设计（系分次重点，了解能判断场景）

体系结构风格 = 一组构件类型、连接件类型和组合约束。

| 风格 | 记住的例子 | 和邻居的差别 |
| --- | --- | --- |
| 批处理 | 传统编译、BAT | 整批传完，前一步结束才开始下一步，步骤间不必有数据依赖 |
| 管道-过滤器 | Unix shell | 前一个输出是后一个输入，可并行。这是和批处理的差别 |
| 主程序/子程序 | 早期结构化 | 单线程调用返回 |
| 面向对象 | Java/C# | 构件是对象 |
| 层次 | Web、数据库 | 只和相邻层说话，同接口可换实现 |
| C/S | 两层或三层（表示、功能、数据） | 资源不对等 |
| 仓库 | IDE、企业数据管理 | 中央数据 + 独立构件 |
| 黑板 | 语音识别、模式识别 | 分级解空间，知识源往黑板上写 |
| 解释器 | 规则可配置的游戏 | 四部件：引擎、代码区、引擎状态、执行进度。灵活但慢 |
| 规则系统 | 专家系统 | 规则集、解释器、选择器、工作内存 |
| 进程通信 | 分布式、微服务 | 构件是独立进程，连接件是消息 |
| 事件 / 隐式调用 | GUI、工具集成 | 广播事件，注册者被自动调用，不直接调用 |
| C2 | — | 构件与连接件都有顶和底，构件不能直接连构件 |
| 闭环过程控制 | 空调、定速巡航 | 反馈把环境拉到新状态 |

架构复用：机会复用（碰到就用）vs 系统复用（事先规划）。产品线 = 共享核心资产、面向特定市场的一组系统。复用三阶段：获取资产 → 管理（构件库）→ 按需求挑选、修改、组装。
