# 6. 软件测试（次重点，选择为主）

| 角度 | 分类 |
| --- | --- |
| 是否看内部 | 黑盒（功能）、白盒（结构）、灰盒（集成时常用，既看输入输出也看内部） |
| 是否运行 | 静态（不运行：审查、结构分析、度量）、动态（构造用例、执行、分析结果） |
| 阶段 | 单元（开发人员，白盒为主）→ 集成 → 系统（黑盒） |
| 对象 | 功能、性能、安全、兼容、界面、易用、稳定 |

**白盒覆盖，发现错误能力从弱到强**

语句 < 判定 ≈ 条件 < 判定条件 < 条件组合 < 路径

- 语句：每条语句至少一次
- 判定：每个判断的真假分支都走到
- 条件：每个小条件的真假都取到，**不保证**整个判断的真假都出现
- 判定条件：两者同时满足
- 条件组合：所有条件真假组合都出现
- 路径：入口到出口的各条路线。考试认定最强，但不要理解成它一定包含全部条件组合

**性能测试辨析（真题爱考）**

| 名称 | 差别 |
| --- | --- |
| 压力测试 | 不断加压，直到某指标到瓶颈。是一个过程 |
| 负载测试 | 已经到达最大负载后，再持续跑一段时间看指标 |
| 并发测试 | 逐渐加负载直到不可接受，看并发能力 |
| 强度测试 | 制造极限状态：超负荷、最差环境、资源下限。不是「慢慢加压」 |
| 容量测试 | 在预先分析出的极限值上，主要功能是否还正常 |
| 配置测试 | 找资源的最优分配，典型客户端/服务器组合 |

单元测试要写两种辅助模块：

- 驱动模块：假装主程序，传数据、收结果
- 桩模块（存根）：代替被测模块调用的下级，只做接口

测试模型：W 模型测试与开发同步；H 模型测试独立、贯穿全程；X 模型针对程序片段编码并测试，频繁交接集成。
