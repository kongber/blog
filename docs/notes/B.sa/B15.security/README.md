# 15. 信息安全（次重点，加密和认证是重点）

安全四块：实体（环境、设备、媒体）、运行（风险、审计、备份、应急）、信息（操作系统、数据库、网络、病毒、访问控制、加密、认证）、人员。

等保五级及适用：

1. 用户自主保护：普通内联网
2. 系统审计保护：联网做商务、需保密的非重要单位
3. 安全标记保护：地方国家机关、金融机构
4. 结构化保护：中央机关、广电等关键部门
5. 访问验证保护：国防和依法特殊隔离的单位

**对称与非对称**

| 算法 | 记什么 |
| --- | --- |
| AES | 128/192/256，当前主流对称 |
| DES | 56 位，已弱 |
| 3DES | 考试写有效密钥 **112 位**（名义 168） |
| IDEA | 128 位，分组 64 |
| RSA | 1024/2048，大整数分解，签名和密钥交换 |
| ECC | 同样安全时密钥更短 |

国密：SM1 分组、芯片里；**SM2 椭圆曲线非对称**（签名、密钥交换、加密）；SM3 杂凑；SM4 分组 128，替代 DES/AES；SM7 非接触卡；**SM9 基于标识的非对称**；ZUC 流密码，用于 LTE。SM2 和 SM9 是非对称，SM3 是杂凑，SM4 是分组。

**数字签名流程**

1. 对原文做 Hash 得摘要（不对整个文件签名）
2. 用签名者**私钥**加密摘要，得到签名
3. 接收方对原文再 Hash，并用签名者**公钥**解开签名，两摘要一致则完整且身份可信

Hash 四特性：易压缩、单向、高灵敏、抗碰撞。SHA-1 已不安全。国密用 SM3。

公钥从哪来信得过：CA 用自己的私钥把用户公钥等信息签成证书。客户端用 CA 公钥验证证书。加密通信时反过来：客户端用服务器公钥加密对称密钥，服务器用私钥解开。签名用私钥加密摘要；保密用对方公钥加密。

密钥体制：KMI 封闭网、有密钥分配中心；PKI 开放网、靠 CA；SPK 规模化专用网（CPK 用椭圆曲线，克服 LPK 的缺陷）。

安全协议：SSL 在传输层，握手后加密；HTTPS 是 HTTP 加上 SSL；PGP 加密邮件，基于 RSA；IPSec 在 IP 层，对上层透明。

单点登录：Kerberos 用票据，向可信第三方认证一次；外壳脚本激活目标平台，口令同步是弱点。

访问控制：DAC 主人自己授权；MAC 比安全标记，管理员定；RBAC 用户-角色-权限，大型系统常用；TBAC 权限随任务变，最小特权；OBAC 把 ACL 挂在对象上，可继承。

模型：

- BLP 保**机密**：不上读、不下写
- Biba 保**完整**：不下读、不上写
- Lattice 是 BLP 加上安全集束，规则仍是不上读、不下写

记忆：保密怕高密流到低处，所以不能下写；完整怕低可信数据污染高处，所以不能上写。
