4. 软件工程概述（重点）

约 1526 字大约 5 分钟

软件工程 = 方法 + 工具 + 过程。PDCA：P 规格说明，D 开发，C 确认，A 演进。

软件过程 = 软件生命周期模型，考试里当同义词。

前提模型
需求完全确定瀑布
初期只有基本需求喷泉、螺旋、RUP、敏捷
形式化规格变换模型

生命周期模型对照（重点，案例考过）

模型一句话致命点
瀑布需求→设计→实现与单元测试→集成与系统测试→运行维护依赖早期需求，不能适应变化
原型 / 演化 / 快速原型考试不区分。需求难一次定清，靠原型迭代用户过早看到不稳定功能会有副作用。特点是迭代
增量按模块逐步交付，每次增量都可独立运行客户能更早用上。和原型的差别：原型是先用原型迭代，增量是直接交付可用子集
螺旋快速原型 + 风险分析适合庞大、高风险；迭代太多会贵、会晚
喷泉面向对象，各阶段重叠、可来回补充没有严格次序
变换形式化规格 + 程序变换要严格数学和整套环境
V 模型开发和测试对应见下表，易错

V 模型测试依据（易错，必背）

测试对象依据
单元模块 / 类详细设计
集成模块之间的接口概要设计
系统完整软件配置项需求分析 / 开发合同
验收准备交付的系统用户需求

不要把「概要设计对面画着系统测试」理解成系统测试依据概要设计。概要设计的产物是集成测试的依据。

迭代 vs 增量：迭代是同一功能螺旋加深；增量是一块块加新功能。两者都降低变更成本；增量能让客户更早获得价值。

RUP（超级重点）

用例驱动、以体系结构为中心、迭代增量。用 4+1 视图描述体系结构。体系结构设计与具体语言无关。

九大核心工作流：业务建模、需求、分析与设计、实现、测试、部署、配置与变更管理、项目管理、环境。2023 年系分直接考过名单。

敏捷（超级重点）

适应型，不是可预测型；以人为本，不是以过程为本；迭代增量。

宣言四句：个体和交互 > 过程和工具；可工作的软件 > 详尽文档；客户合作 > 合同谈判；响应变化 > 遵循计划。

适用：规模较小、需求还在变。高关键、高可靠、高安全不一定适合。口诀：小变。

方法记什么
XP交流、朴素、反馈、勇气；YAGNI、DRY
水晶以人为中心
Scrum管项目的迭代增量框架
FDD特征驱动，人、过程、技术

Scrum

  • 角色：Product Owner（排优先级、管 Product Backlog）、Scrum Master（护流程、清障碍）、Development Team（自组织交付）
  • 事件：Sprint（通常 1～4 周，交付潜在可发布增量）、Sprint Planning、Daily Scrum、Sprint Review
  • 工件：Product Backlog、Sprint Backlog、Increment（满足 DoD）
  • 经验过程：透明、检查、调整

过程改进

CMM 五级：初始 → 可重复 → 已定义 → 已管理 → 优化。口诀：除虫顶管用。

  • 初始：靠高手和运气
  • 可重复：项目级能跟踪成本、进度、功能
  • 已定义：组织级标准过程，已文档化
  • 已管理：定量度量
  • 优化：持续改进

CMMI 是升级版，整合系统工程与软件工程，适合集成企业。知识体系：系统工程、软件工程、集成产品与流程开发、供应商采购。口诀：细软开工。

CMMI 五级：初始 → 已管理 → 已定义 → 量化管理 → 优化。口诀：储罐定粮油。

易混：CMM 第二级叫可重复，第三级已定义，第四级已管理。CMMI 第二级就叫已管理，第四级叫量化管理。

逆向工程（次重点，选择考过多次）

概念含义
逆向工程从代码恢复更高层设计
重构同一抽象层改结构，不升不降
设计恢复用工具抽出数据设计、总体结构、过程设计
再工程逆向 + 考虑新需求 + 正向，产生新版本
正向工程从设计到代码

抽象层次从低到高：实现级 → 结构级 → 功能级 → 领域级。口诀：世仇结分工龄。

净室（次重点）

它是形式化方法，不是测试方法。理论基础：函数理论（程序 = 输入到输出的函数；完备、一致、正确）+ 抽样理论（用统计抽样推断可靠性）。

要点：正确性验证成本高；不靠传统单元测试，但仍要模块测试；解决不了所有工程问题。

基于构件 CBSE（超级重点）

构件特性（萨默维尔，选择爱考）：可组装、可部署（二进制、自包含）、文档化、独立、标准化，以及无外部可见状态。口诀：竹鼠挡毒标。

外部形态五类：独立而成熟（如 DBMS、OS）、有限制（基础类库）、适应性（ActiveX）、装配的（胶水代码连接）、可修改的。口诀：独显时装秀。

基于复用的开发大致顺序：需求概览 → 识别候选构件 → 按找到的构件改需求 → 体系结构 → 定制与适配 → 组装。需求可以被已有构件反过来改。

三种组装

方式要点
顺序组装先调 A 再用结果调 B，构件彼此不调用，常要胶水代码
层次组装A 直接调用 B。接口匹配则不用额外代码；不匹配要转换。网络服务形态不能用层次组装硬套
叠加组装新接口是原接口的并集，外部接口分别调用，构件互不调用

接口不兼容三类：参数不兼容（名字同、参数不同）、操作不兼容（操作名不同）、操作不完备（一边是另一边的子集）。

构件图：提供接口是小圆（棒糖），请求接口是半圆插座。
