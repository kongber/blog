14. 数据库系统（超级重点）

约 2099 字大约 7 分钟

案例常考：模式、规范化、并发、完整性、ER。也开始考分区、反规范化、主从、一致性，那些在案例冲刺材料里。

三级模式、两级映射

模式谁看描述什么
外模式用户局部逻辑，用户视图
概念模式DBA全体数据的逻辑结构和联系
内模式系统程序员物理存储、索引、路径

口诀：外局改全内务。

  • 物理独立性：应用与磁盘存储无关。内模式变，改内模式到概念模式的映射
  • 逻辑独立性：应用与逻辑结构无关。概念模式变，改外模式到概念模式的映射

关系术语：关系=表，元组=行，属性=列，域=取值范围，主码=选出的那个候选码，主属性=出现在任一候选码里的属性，非主属性=哪个候选码都不含。

关系代数（要能翻译成 SQL）

运算含义SQL 直觉
并 ∪两边都要，列数相同UNION
差 −在 R 不在 SEXCEPT
交 ∩两边都有INTERSECT
笛卡尔积 ×所有配对，列拼起来，行数相乘FROM R, S
选择 σ按行挑WHERE
投影 π按列挑SELECT 列
自然连接同名属性相等，去掉重复列JOIN USING / NATURAL JOIN

除法考到可放弃。元组演算最多 1 分：{t | P(t)}，∃ 是存在，∀ 是所有，∧∨¬ 是与或非。

设计阶段

规划 → 需求分析（DFD、数据字典）→ 概念设计（分 ER、合并）→ 逻辑设计（ER 转关系、规范化）→ 物理设计。最重要的是概念和逻辑。概念设计常用：需求自顶向下，结构自底向上。

ER：实体矩形，属性椭圆，多值属性双线椭圆，派生属性虚线椭圆，联系菱形，连线上标 1:1、1:n、m:n。

  • 弱实体：离不开强实体，如订单离不开用户
  • 不完全概化：父实体可以不属于任何子类
  • 全部概化：父实体每个实例都必须落入某个子类

合并全局 ER：先按公共实体合并，再消冲突（属性域/取值、同名异义与异名同义、同一对象抽象不一致），再消冗余属性和冗余联系。

ER 转关系（案例要会写表）

联系怎么变
1:1单独成表，主键任取一端；或并进任意一端，把另一端主键拿过来
1:n单独成表，主键是 n 端主键；或并进 n 端，把 1 端主键拿过来
m:n只能单独成表，主键是两端主键的组合

函数依赖与键

  • 平凡：右边是左边的子集
  • 非平凡：右边不是左边的子集
  • 完全：左边任何真子集都不能决定右边
  • 部分：左边有真子集已经能决定右边
  • 传递：X→Y→Z，Y 不能决定 X，Z 不是 Y 的子集

Armstrong 常用：自反、增广（两边同加）、传递、合并（同一左边合成）、分解（右边拆开）。

候选码图示法：属性做点，依赖做弧。入度 0 的属性集若能走到全部结点，就是候选码；走不到就把中间点并进来再试。

无损连接（只分解成两个时）：R1∩R2 → R1−R2，或 R1∩R2 → R2−R1，有一个成立即可。

保持函数依赖：分解后各模式上的依赖合起来，要和原来的 F 等价。无损和保持依赖互不蕴含。

四大异常（案例至少能写满）

关系里课程教师信息跟着每个选课学生重复：

  • 冗余：同一教师地址存 100 次
  • 修改异常：改地址要改 100 处，否则不一致
  • 插入异常：还没有学生时，教师信息进不去，或被迫插空
  • 删除异常：删掉课程就把学生信息一起删了

口诀：绒绣茶山。

范式（案例必考，先找候选码再判断）

范式条件怎么拆
1NF每个属性都是原子值把「高级职称人数」拆成教授人数、副教授人数
2NF在 1NF 上，非主属性对候选码没有部分依赖。候选码都是单属性则自动 2NF（学号，课程号）这种联合码，把只依赖学号的列拆到学生表，只依赖课程号的拆到课程表，成绩留在选课表
3NF非主属性对候选码没有传递依赖。没有非主属性则一定是 3NF学号→学校编号→学校地址，把学校拆出去
BCNF每个非平凡函数依赖的左边都必须是超码。主属性也不许当「非码决定因素」教工号→课程号，但教工号不是码，拆成（学号，教工号）和（教工号，课程号）
4NF同一关系里不要同时存在多个独立的多值依赖孩子和选修课拆成两张表

推论：3NF 一定是 2NF。因为部分依赖能推出传递依赖。2NF 不要求先写「已满足 3NF」，但判断时从低往高看。

键：超码可以有多余属性；候选码是最小超码；主键是选中的那个候选码；主属性属于任一候选码。

事务与并发（重点）

ACID：

  • 原子性：全做或全不做
  • 一致性：从一个一致状态到另一个。转账总额不变
  • 隔离性：并发看起来像串行
  • 持久性：提交之后永久有效

四个并发问题：

问题场景
丢失修改两个事务都读到旧值再写回，后写覆盖先写。分回滚覆盖已提交，和后提交覆盖先提交
脏读读到别人还没提交、后来又撤销的值
不可重复读同一事务两次读，中间被别人改了，两次结果不同
幻读两次按范围读，中间被插入，行数变了。本质仍是不可重复读，差别是插入

锁：

  • X 排他锁：自己可读可写，别人什么锁都不能加
  • S 共享锁：大家都能读，都不能再加 X

封锁协议能解决到哪：

协议能防不能防
一级：改之前加 X，事务结束才放丢失修改脏读、不可重复读
二级：读之前加 S，读完就放丢失修改、脏读不可重复读
三级：读之前加 S，事务结束才放上面三个都能—
两段锁：先全部申请（扩展），再只释放不再申请（收缩）遵守则调度可串行化仍可能死锁

封锁粒度越小并发越高、开销越大；粒度越大相反。

性能、完整性、备份、仓库

反规范化：把常用汇总值存进表、减少跨表、水平或垂直分割。代价还是那四个异常。

索引：建在常查、不常改的列上；索引太多会拖慢增删改；很小的表不必建，直接扫更快。

完整性：

  • 实体完整性：主键不能空
  • 参照完整性：外键要么空，要么等于被参照表的主键。违反时：级联、受限、置空
  • 用户定义：年龄 18～60 这类业务规则
  • 触发器：BEFORE/AFTER + INSERT/UPDATE/DELETE，不能直接挂在 SELECT 上。INSERT 只有 NEW，DELETE 只有 OLD，UPDATE 两者都有

备份：物理备份拷文件，恢复快；逻辑备份导出对象，灵活、可跨平台。完全备份最慢最全；增量只备上次任意备份之后的变化，恢复要全套按序；差异只备上次完全备份之后的变化，恢复只要「完全 + 最近一次差异」。

OLTP vs OLAP：

OLTPOLAP
谁用操作人员决策人员
设计面向应用面向主题
数据当前、细节、二维历史、聚集、多维
操作读写几十行读上百万行
库MB～GBGB～TB

多维操作：钻取（改粒度）、切片（剩两维）、切块（剩三维及以上）、旋转（行列互换）。

分布式：逻辑独立、物理独立，再加分布透明。局部自治 + 全局协调。可以适度冗余换可靠和性能。模式从上到下：全局外模式、全局概念模式、分片模式、分布模式、局部概念模式、局部内模式。

分片：水平用并还原；垂直必须各片都留关键字，用连接还原；导出分片的条件来自别的关系；混合两者都用。
